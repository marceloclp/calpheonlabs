The production decoder is offset-independent. The companion
`itemenchantoffset.dbss` table was used only as an oracle to enumerate and
strictly bound every build-2954 row while deriving the schemas. Each complete
row schema owns its counts and string lengths and validates the repeated packed
item/enhancement key at the trailer. No interface, custom reader, cursor state,
lookahead, or offset-table dependency remains.

## Schema composition

The complete `ItemEnchantRow` union is the cross-product actually exercised by
the installed capture, not a permissive cross-product of hypothetical layouts.
Its literal `layout` identifies six physical axes in order:

`pre-name / post-market prefix / middle / pre-text / post-text / suffix`

| Component          | Physical representation                                                                                          | Confidence and evidence                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `fixed`            | One 212-byte struct containing the packed item identity, item/trade controls, prices, and retained opaque fields | Certain; shared by all 168,708 rows                                         |
| `preName`          | Four explicit counted-list structs: `standard`, `five`, `byte-five`, and `word-five`                             | Certain; 166,274 / 1,869 / 564 / 1 rows                                     |
| `texts`            | One struct containing the scalar before the name, five framed strings, and lossless decimal `u64` market limit   | Certain physical representation; semantic confidence varies by field        |
| `postMarketPrefix` | Eight explicit fixed-width structs: 168, 164, 180, 140, 116, 125, 126, and 132 bytes                             | Certain; 166,648 / 437 / 54 / 1,066 / 30 / 458 / 4 / 11 rows                |
| `postMarketLists`  | Three counted lists with fixed separators                                                                        | Certain; every count owns its following elements and reaches the next seam  |
| `tail.middle`      | Fourteen explicit fixed-width structs: 36, 48, 50, 52, 64, 76, 88, 104, 108, 116, 122, 123, 228, and 280 bytes   | Certain; all widths are exercised and companion-bounded                     |
| `tail.preText`     | Eight explicit widths: direct, 4, 8, 12, 16, 20, 24, and 28 bytes                                                | Certain; 81,209 / 27,705 / 24,010 / 14,056 / 14,100 / 7,002 / 608 / 18 rows |
| `tail.postText`    | Direct or a 12-byte expansion                                                                                    | Certain; 168,700 / 8 rows                                                   |
| `tail.suffix`      | 15-byte, 17-byte, or counted-`u16` trailer struct, followed by repeated key and retained `u16` value             | Certain; 167,495 / 1,134 / 79 rows                                          |
| Complete row check | Packed `fixed.itemId` plus `fixed.enhancementLevel` equals `tail.suffix.repeatedRowKey`                          | Certain; 168,708 / 168,708 rows                                             |

The final trailer half-word is deliberately not asserted to be `0xffff`:
168,224 rows have that value, while 484 rows exercise other values. It is
retained as data.
