See [Decoder methodology](/methodology). The migrated production decoder has
no offset-table import, search primitive, preview, or next-row probe. One
212-byte fixed schema is followed by an ordered union of the four exercised
pre-name list layouts. Six later counted arrays complete the eight arrays in
the row, while eight length-prefixed strings consume their text regions
linearly through the repeated-key trailer. The CLI loader applies the same row
schema to bounded frame views; its initial 8 KiB frame doubles when necessary
and therefore is not a row-size limit.

## Active assumptions

:::success[No active assumptions affecting snapshot parity]
The four bytes before `tailValues16` have one capture-equivalent provenance
ambiguity: they may be one `u32`, `u16` plus two zero padding bytes, or `u8`
plus three zero padding bytes. All interpretations consume the same bytes and
emit the same 0..3 array lengths in the examined capture. The schema uses the
table's prevailing four-byte array framing without claiming that the producer
conceptually owns all four bytes as count bits.
:::
